# Deploy Bot 使用介绍 08：怎么发起部署、查看记录与详情

到这一步，前面的配置链路已经齐了。  
这一篇只看用户真正怎么用它发版、回看历史和排查问题。

## 1. 流水线大厅是发版入口

真正最常用的页面是流水线大厅：

![流水线大厅](../screenshots/user-pipelines.png)

这页通常会做几件事：

- 找到目标流水线
- 按标签、类型、关键词筛选
- 触发部署
- 看当前状态
- 进入历史或详情

如果你是日常发版的人，这一页基本就是首页。

## 2. 发起部署时一般关注什么

触发部署前，通常会先看：

- 当前是不是要发正确的那条流水线
- 分支是不是对的
- 最近一次部署是不是刚失败过
- 运行中的服务是不是还正常

如果这些都正常，再点部署就好。

## 3. 部署记录页适合看什么

每次执行后，都会进入部署记录：

![部署记录](../screenshots/user-deployments.png)

这个页面更适合做全局回看，例如：

- 我今天发了哪几次
- 哪几次成功、哪几次失败
- 某条线是不是反复失败
- 哪次可以直接回滚

## 4. 详情页才是排查核心

真正出了问题，还是要进部署详情：

![部署详情](../screenshots/user-deployment-detail.png)

这页会同时给你四类信息：

- 当前执行状态
- 执行日志
- 时间信息和耗时
- 部署快照

### 为什么部署快照很重要

因为很多失败并不是脚本写错，而是：

- 环境变了
- 变量值变了
- YAML 配置变了
- 启动参数变了

快照会把那次部署真正使用的上下文固化下来，后面回头对比问题会轻松很多。

## 5. 流水线历史和部署记录有什么区别

如果你只想看某一条线，就进流水线历史：

![流水线历史](../screenshots/user-pipeline-history.png)

它和全局部署记录的区别可以简单理解成：

- `部署记录`
  所有流水线混在一起看
- `流水线历史`
  只看这一条线自己的连续变化

这对排查“同一条线从哪次开始坏掉”特别有帮助。

## 6. 回滚应该怎么理解

当前平台里的“回滚到此版本”，本质上是：

- 基于历史成功产物
- 再创建一条新的部署记录
- 把那份历史产物重新发布出去

它不是重新拉代码、重新构建。  
所以如果你要快速恢复到上一个稳定版本，这个动作会比重新发版更直接。

## 7. 推荐的实际使用顺序

日常使用时，比较顺手的方式通常是：

1. 先从流水线大厅触发部署
2. 需要盯进度就直接进部署详情
3. 发布完以后回到部署记录看整体结果
4. 如果某条线连续有问题，再进流水线历史做连续对比

到这里，部署主链路就完整了。后面再配合服务、通知和系统设置，就能把整套使用链路补齐。
